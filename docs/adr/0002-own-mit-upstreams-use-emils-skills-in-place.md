# Friday owns copies of Matt's and pstack's skills, and uses Emil's in place

Friday copies the Matt Pocock and pstack skills it keeps into its own repo and edits them freely (owned skills), but uses Emil Kowalski's skills exactly as installed, never edited, copied or renamed (in-place skills), with Friday's own skills calling them by name. The split follows the licences: Matt's skills and pstack are MIT, while Emil's paid course skills ship with no licence or published terms, so changing them is not granted. Ownership is also the only way to cut, merge or rename single skills, since a Claude Code plugin is switched on or off as a whole. pstack has installed in Claude Code since 2026-10-16, but in place it would still come as all 56 skills or none, its rules against stopping for Somya and its non-Claude review seats couldn't be edited, and Friday's skills could reach its files only through a cache path that changes with every release. Decided in "Does Friday use upstream skills in place or copy and own them?" (somyanath/friday#9, 2026-10-15); the pstack reason changed in "Now that pstack installs in Claude Code, does Friday still own copies of it?" (somyanath/friday#20, 2026-10-21), which kept the decision.

## Consequences

- **Upstream changes come in only through an Upstream check, run when Somya asks.** Each owned skill records the upstream files it came from, and Friday records, per upstream, the commit it last reviewed up to. An agent reads everything the upstream changed since that commit in one pass, comparing the upstream with itself (never with Friday's copies) and reading each PR's description. Each change is tested for fit against Friday's ADRs and glossary and for worth, and gets adopt, adapt or skip; a new upstream piece gets keep or cut. The result is one PR in Friday's repo whose description is the report. Somya drops what they reject, and merging moves the reviewed-to commit forward, so a skipped change is never proposed again. The same check covers Matt's and pstack's skills. Detailed in somyanath/friday#20.
- **Owned pstack copies start from pstack's source** (`pstack/skills`, `pstack/agents`) at a pinned commit, not its generated Claude Code tree, and are written in Claude Code names. pstack's Claude Code adapter isn't carried, since it tells agents "Do not stop, ask, or retry" and runs non-Claude seats on the session model; a non-Claude seat becomes a Codex call (ADR-0001). Any copy that tells agents not to stop names the gates, the Always-pause list and a Rule conflict as exceptions. (somyanath/friday#20)
- **Friday's setup never installs pstack's own plugin.** A proposed change is tried from the Upstream check's PR branch with `--plugin-dir`. (somyanath/friday#20)
- Emil's updates arrive by Somya reinstalling them, which overwrites them in place. Friday then checks its list of the Emil skills it calls or switches off, flagging any that are missing, renamed, new or changed.
- Owned skills are prefixed `matt-` or `pstack-` when copied from one upstream, and `friday-` when built from more than one upstream or written from scratch. Emil's names never change, so a prefixed skill can never collide with one of his.
- Once Friday's copies work, Matt's plugin is switched off wherever Friday is on, so no skill exists twice.
